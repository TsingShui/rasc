# Diana 开发流程：小批闭环，不按目录计进度

本页记录**怎样开发**：批次范围、开工条件、完成标准、停止条件和证据落点。
不再为同一流程新增 E2E_METHOD/DEV_METHOD 等另一套文档，也不建立通用任务平台。

**当前状态**：只有工程骨架和 70 个案例设计稿，没有 Engine、可运行 fixture 或
E2E runner。小批闭环的纪律记录于此；下文“按批认证后开始对应实现”涉及修改
现有全量前置规则，**仍待明确确认，未生效**。在完成该决定及文档同步之前，
继续执行 [TEST_PREPARATION.md](TEST_PREPARATION.md) 的全量 B01–B04 前置，
不得凭本页提前启动 T01/H01 功能实现。记录流程不等于任何任务已完成。

| 本页 DEVELOPMENT.md | 怎样切批、验收、停手、记录进展 |
| [TEST_PREPARATION.md](TEST_PREPARATION.md) | B01–B04 的准备/认证标准和当前有效前置规则 |
| [e2e_cases.json](e2e_cases.json) / [E2E_CASES.md](E2E_CASES.md) | 问题、独立期望、oracle、固定案例身份，不保存引擎当前通过结果 |
| [TASKS.md](TASKS.md) / [PROJECT_TASKS.md](PROJECT_TASKS.md) | T/H 能力职责、依赖和最终完成要求，不另当每日进度表 |
| 实际开工后创建的 `docs/diana/batches/<id>.md` | 每批范围、证据、结果与下一步；不开工不创建空批次目录 |

[STRUCTURE.md](STRUCTURE.md) 解释当前目录；两者不重复维护一套批次结果。

签入的批次记录保留命令、摘要、版本/hash 和可复建配方，不引用个人磁盘路径。

## 2. 一个批次只有一个可观察目标

```text
选定语义义务与固定案例
→ 先审阅问题/独立期望，认证输入和比较器
→ 确认适用的生产实现前置已满足
→ 运行真实失败测试，定位负责的决策
→ 实现最小必要路径
→ 当前案例与已验收回归通过
→ 审阅、记录并结束本批
```

- 按公开库/复杂领域 module 的行为交付，不按新增文件、phase 目录或代码行数交付。
- 一次只推进一个批次；先单 writer，不因任务大自动启动子 Agent 或并行改共享接口。
- T/H 是职责与最终合同。一个有界批次可以只完成其中一部分；部分完成要如实记录，
  **不跳过有效依赖，也不把批次完成等同整张 T/H 卡完成**。
- 只创建当前路径实际消费的 module，不先铺 P0–P9 空文件、插件/通用调度框架或缓存。
- 核心正确性修复直接修，不能变成“关闭时允许错误”的产品选项。只有可选美化
  才使用 off/on 验证；本项目仍默认关闭，不照搬其他项目的自动默认开启条件。
- 测试经过公开 interface，不冻结私有 CFG/Phi/AST 形状、内部调用次数、变量名或排版。
  阶段 dump 可辅助定位，包括失败 CI 的诊断产物，但不是必须字节匹配的验收 golden。
- 缩小能力覆盖不等于省掉当前路径的输入校验、预算、取消或原始语义义务。
  暂不能可信处理的格式要诚实拒绝，不以猜测宽度、默认值或半源码冒充成功。

## 3. 准备规则的唯一待确认调整

**现行规则**：70 案例的全量 B01–B04 准备验收先于生产实现。
可以先做准备工具的单案例试点，但试点通过不能代替全量 B04。

**建议变更（未生效）**：

1. 70 个问题、独立预期与 required 总范围先经 B01 审阅；设计草案不自动当已认证真值。
2. B02–B04 的执行资产按有界案例批准备；每批的 source/输入结构/工具锁/参考行为/
   比较器证伪，必须在该批生产实现之前通过。
3. 尚未准备的案例保留在总账，不从 required 删除；跨批共用的工具和比较器一旦变更，
   重验受影响的已认证输入与已验收能力。批次不得暗中扩展到未认证的下一种语义。
4. 全量 B02/B03/B04 仍只有全部 required 资产达标才能称完成；局部 ready 不是全量完成。

若用户确认，再**一次同步**本页、AGENTS、TEST_PREPARATION、实施依赖与有关任务卡，
清楚区分全量完成与批次就绪，然后开始对应实现。此前不把 B04 解释为局部通过，
不改既有 DAG、案例内容或期望。本次只记录建议，不实施这项规则变更。

## 4. 建议的早期顺序，不是已授权执行计划

| 小批目标 | 固定案例/证据 | 明确不做 |
|---|---|---|
| 最小验证装置试点 | D009：自制源、独立溢出预期、JVM Driver、生成 DEX 结构认证；错返回/编译失败/缺产物必须被拒绝 | 不实现或伪造 Engine，不搭全能测试平台 |
| 第一条真实反编译链 | D009 经公开库恢复 Java 后编译运行；D055 非法 count 拒绝；D059 未知格式诚实 Unavailable | 不一次覆盖全部 opcode、metadata、整类恢复或接完整 CLI |
| 第一个分支合流 | D001 全部固定输入与独立结果，复跑前批 | 不做变量合并或表达式美化 |
| 循环平行拷贝 | D002，再 D003；按交换/旋转错误变体分别验收 | 不顺带加入复杂异常或 monitor |

每行开工前仍须具体批次记录与适用的准备前置；不是把多行合并成一个大任务。
不为通过指定输入硬编码结果、识别 case ID 或绕过原始字节。后续按真实证据再选
调用副作用、异常旧值等下一批，不提前展开全部实现细节。
GUI、Web UI、MCP、美化、并行、性能优化与真实语料扩张均不进入这些首批。

## 5. 批次完成与停止条件

**完成要同时满足**：
- 当前固定案例在约定公开 seam 上有真实非零证据，语言/错误状态也符合预期；
  原程序参考通过、恢复 Java 可编译或 assembler 成功，单独都不算语义通过。
- 比较器拒绝对应的错误变体；已验收相关案例不回归，适用的 Diana-only gate 通过。
- 目标输入/期望没有随 actual 刷新；局限、未实现和未验证平台如实列出。
- 本批“不做清单”没有被顺手实现，留下明确可审阅结果后结束，而非继续找下一项塞入。

**出现以下情况先停手**：
- 需要改变公共 interface/语义合同、冻结的 expected 或有效依赖；先写理由并独立审阅。
- 输入/工具/oracle 无法独立认证；记 blocked，不用引擎输出来填缺失答案。
- 为一个案例开始开发通用框架，或混入第二个无关语义问题；拆出后续候选，不直接扩批。
- 连续尝试没有增加任何定位证据；回到最小复现与负责决策，不跨 phase 盲目打补丁。

blocked/负结果是有效记录，但不是能力验收通过。只有独立证据证明规范确有错误，
才按 TEST_PREPARATION 的修正纪律修改测试，不能把“永不改测试”变成固化错误 oracle。

## 6. 开工时复制的最小批次记录

只在真正开始该批时创建一份 Markdown，不增加 JSON schema/数据库或多处手填计数：

```text
# <批次名>
状态：计划 / 准备中 / 实现中 / 已验收 / blocked（以证据说明）
目标：一个调用方可观察到的行为
案例：固定 D 编号、规范 revision；复跑哪些已验收案例
职责：关联 T/H，仅本批覆盖部分；有效依赖是否满足
不做：本批禁止顺手扩展的内容
准备证据：来源/工具锁/输入 hash、独立 expected、错误变体拒绝结果
验收：公开 seam、具体命令与应有行为
结果：实际执行数、失败/未运行原因、适用平台、产物相对路径、下一步
```

总账分开记录**输入准备状态**与**引擎验证状态**：输入未准备不等于引擎已失败，
引擎未实现也不能标 skip/pass。报告当前批与已验收回归，并保留完整 70 案例分母，
不得只展示一个挑选后的绿色集合。批次记录不复制或重定义 expected。

衡量进展只问：新增了什么真实能力、已有能力是否回归、本批是否按边界及时结束。

## 7. 从 Kuna 借纪律，不照搬整个流程

参考版本与来源见 [SOURCE_MAP.md](SOURCE_MAP.md)。借鉴其先复现/确认信号、
定位负责决策、小改可审阅、大改先设计、保留负结果和真实前后证据的纪律。
Kuna 明确禁止重钉核心 baseline，不能把它描述成“随意改当前通过集合”。
但文本形状/回归 baseline 不替代 Diana 的独立行为 oracle；不据部分测试文件
断言 Kuna 整个项目没有比较器证伪测试，也不移植其所有开关、登记器或自动化流水线。
