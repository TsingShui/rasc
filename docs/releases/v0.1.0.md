# rasc v0.1.0

First tagged release of rasc, the native Rust APK/DEX analysis CLI.

## Highlights

- **`getclass` renders Java through a vendored `dexdec`** (a jadx-aligned Rust
  decompiler) instead of the in-tree emitter that used to ship in `rasc-dex`.
  The old emitter's wrong-output families - constructor delegation, Kotlin
  default arguments, shared join blocks, `synchronized`, phi merges - are gone
  with it. When the decompiler cannot handle a class, the command fails; it does
  not print Java that might be wrong.
- **The DEX parser decodes names on demand.** Strings keep a byte range into the
  image, type/field/method/proto ids store their rows, and the class directory
  defers annotation decoding. On a 10 MiB DEX the parse phases fell from ~45 ms
  to ~8.4 ms, and the class-directory phase from 16.3 ms to 1.8 ms.
- **Targets: native and `wasm32-unknown-unknown`** (the browser/JS host module).
  `wasm32-wasip1` was removed, and the gates now run the CLI tier first,
  skipping the wasm tier while the CLI tier is red.

## Performance

The reference comparison: 11 scenarios over a 343 MiB APK, one machine, median
of N runs, fresh process per measurement:

| Scenario | rasc | reference | speedup |
|---|---:|---:|---:|
| findrefs string | 132 ms | 638 ms | 4.8x |
| findrefs type | 166 ms | 1047 ms | 6.3x |
| findrefs method | 174 ms | 1379 ms | 7.9x |
| findrefs field | 198 ms | 1762 ms | 8.9x |
| getclass, early DEX | 62 ms | 137 ms | 2.2x |
| getclass, late DEX | 87 ms | 323 ms | 3.7x |
| getclass, missing class | 55 ms | 357 ms | 6.4x |
| manifest | 17 ms | 334 ms | 20.1x |
| classes (567k classes) | 97 ms | 2733 ms | 28.2x |
| **geometric mean** | | | **7.1x** |

Every scenario validates exit status and result sets before any timing is
reported.

## Artifacts

- `rasc-v0.1.0-aarch64-apple-darwin.tar.gz` - Apple Silicon
- `rasc-v0.1.0-x86_64-apple-darwin.tar.gz` - Intel (runs under Rosetta on Apple
  Silicon)

Each archive holds the `rasc` binary, `LICENSE`, `NOTICE` and both READMEs, with
a `.sha256` beside it. The binaries are not signed or notarized, so macOS may ask
for a Gatekeeper confirmation on first run.

## Notes

- `--emitter` and the smali fallback were removed with `rasc-dex`; the audit
  harness went with the crate.
- The release profile uses thin LTO.
